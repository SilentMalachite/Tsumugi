# 運用ガイド（Tsumugi）

オフライン専用デスクトップアプリの配布・初回セットアップ・日常運用の手順。詳細な設計判断は ADR を正とする。

---

## 1. 対応 OS と発行物の作成・配布

対応する発行ターゲットは次のとおり（[ADR 0054](decisions/0054-distribution-configuration.md)）。

| OS | RID | スクリプト |
|---|---|---|
| macOS | `osx-arm64` | `build/publish.sh` |
| Windows | `win-x64` | `build/publish.ps1` |

共通条件: Release、self-contained、単一ファイル、trim 無効。成果物は `artifacts/publish/<RID>/` に生成し、リポジトリへコミットしない。

### 発行例

リポジトリルートで実行する。

```bash
# macOS (osx-arm64)
./build/publish.sh
```

```powershell
# Windows (win-x64)
.\build\publish.ps1
```

どちらのスクリプトも `dotnet publish` が失敗した時点で中断し、非ゼロの終了コードを返す。**発行後は必ず終了コードを確認する**（`echo $?` / `$LASTEXITCODE`）。0 以外なら成果物は不完全なので配布しない。

**配布単位は `artifacts/publish/<RID>/` ディレクトリ全体**。実行ファイル1個だけをコピーしてはいけない。`PublishSingleFile` はマネージドアセンブリのみを束ねる設定（`IncludeNativeLibrariesForSelfExtract` は立てていない）なので、次が実行ファイルの隣にサイドカーとして残る。

- Avalonia のネイティブライブラリ（`libSkiaSharp` / `libHarfBuzzSharp` など）— 欠けると起動時に描画初期化で失敗する
- `NOTICE` と `assets/fonts/NotoSansJP.LICENSE.txt` — 欠けるとライセンス表示義務を満たさないまま配布される

このディレクトリを対象端末へオフラインでコピーする。インストーラ・コード署名・オンライン更新は対象外（ADR 0054）。

Windows 実機での起動確認は別途 `docs/manual-qa.md` を参照する（未実施の行が残る場合がある）。

## 2. 初回セットアップ

事業所が未登録の DB（Office 0 件）で起動すると、初回セットアップウィザードが表示される。通常の MainWindow は登録成功後にだけ開く。キャンセルまたはウィンドウを閉じるとアプリは終了し、次回起動で再度ウィザードが出る。

### 入力項目

必須:

- 事業所番号
- 事業所名
- サービス種別（既定は就労継続支援B型）
- 地域区分（`RegionGrade.None` は登録不可。級地を必ず選ぶ）

任意（初回で入力を促す）:

- 郵便番号・住所・電話番号
- 管理者（職氏名）

### 登録後に既存画面で行う設定

ウィザードでは請求プロファイルと体制届は扱わない。事業所登録後、既存の事業所・体制届画面から次を設定する。

- 請求プロファイル（施設区分など）
- 体制届オプション

未設定のままだと、処遇改善加算などを宣言している月の preview／確定が fail-close しうる。請求前に確認する。

### 登録後に画面が切り替わらない場合

登録は完了したが MainWindow への切り替えに失敗した場合、ウィザードに「登録は完了しましたが、画面の切り替えに失敗しました」と表示され、登録ボタンは無効になる。**もう一度登録し直さない**（事業所は既に保存済みで、再実行しても「既に登録されています」になるだけ）。キャンセルでアプリを終了し、再起動する。再起動時は Office が 1 件あるため、ウィザードではなく通常画面が開く。

### 起動に失敗した場合

DB の破損・ロックなどで起動処理が失敗すると、「起動に失敗しました」画面が開き、エラーの種別だけが表示される。閉じるとアプリは終了する（終了時バックアップは通る）。表示された種別は §6 の連絡前確認に沿ってそのまま伝えてよい（保存先パスや氏名は含まれない）。

DB の保存先実体パスは OS・環境変数で変動する。固定パスは本ガイドに書かない。[ADR 0003](decisions/0003-sqlite-location-and-encryption.md) を参照する。

## 3. 日常バックアップ・復元

正本は [ADR 0052](decisions/0052-backup-operations.md)。

### 自動バックアップ

アプリ終了時に、固定の backups ディレクトリへ自動でバックアップを取る（常時オン・設定項目なし）。世代管理は「同日は最新1つ・直近7日分」。ファイルは平文である。

### 手動「控えを保存」

画面から利用者が保存先を選んで控えを書き出せる。外部媒体へ出たコピーにも権限ポリシーは適用されない（ADR 0052）。持ち出し時は媒体の取り扱いに注意する。

### 復元

画面上では、固定 backups ディレクトリ内の世代一覧から選んで復元する。復元が成功するとアプリは終了する。再起動後に復元後の DB で運用する。

### 外部控えを戻す場合の制約（現状）

「控えを保存」で外部へ出したファイルを、画面のファイルピッカーから直接戻す手段は無い。復旧するには、利用者がそのファイルを固定 backups ディレクトリへ手動コピーしたうえで、世代一覧から復元する必要がある。ディレクトリの実体パスは画面にもログにも出さない（ハード制約）。場所の一般規則は [ADR 0003](decisions/0003-sqlite-location-and-encryption.md)／[ADR 0052](decisions/0052-backup-operations.md) を参照する。

## 4. FileVault／BitLocker

DB 本体は暗号化しない（平文＋OS ファイル権限）。端末盗難対策は **FileVault（macOS）／BitLocker（Windows）の有効化** に委譲する。

理由（共有 OS アカウント運用では DB 暗号化が職員間分離にならない、鍵紛失が許容できない、等）と再評価トリガ（職員別 OS アカウント化・端末持ち出し・鍵管理の用意）は [ADR 0003](decisions/0003-sqlite-location-and-encryption.md) の追補「暗号化採否の確定」を正とする。本ガイドでは繰り返さない。

運用開始前に、対象端末で FileVault／BitLocker が有効であることを確認する。

## 5. 請求 CSV の責務境界

アプリの責務は、仕様準拠の請求データ（CSV）を生成し、公式の取込・送信システムにインポートできる状態までに限る。

次はアプリの範囲外である。

- 伝送
- 電子証明書
- 回線処理

国保連への送信は公式システム側で行う。

## 6. 障害時の連絡前確認

問い合わせ文・スクリーンショット・ログ・メールに、次を含めない。

- 利用者の氏名
- 受給者証番号
- DB やバックアップのフルパス

再現手順は「どの画面のどの操作か」「エラー文言の安全な要約」「処理対象年月」など、個人情報とパスを含まない形で伝える。保存先の一般規則が必要な場合は ADR 0003 への参照にとどめる。
