# 0033 登録済み一次資料（共通編・事業所編）から CSV 仕様適合を確定する

- 状態: 採用（2026-07-25）
- 関連: ADR 0024（国保連CSVと項目マッピング）/ ADR 0032（契約情報の個別入力）
- 一次資料: `common-r7-10`（インタフェース仕様書 共通編、SHA-256 `f6932c52a4fd1044…`、482,854 bytes）
  / `provider-r7-10`（同 事業所編、SHA-256 `44e94a7817bde2b9…`、1,725,930 bytes）
  いずれも `sources.json` に登録済みで、2026-07-25 に再取得して登録 SHA-256 と一致を確認し
  `liveCheck` を記録した。

## 結論

Phase 3-3 の実装で推測に頼っていた 5 点を、登録済み一次資料の該当条文から確定した。うち
**3 点は実装が公式仕様に違反していた**ため修正した。

| 項目 | 出典 | 確定内容 | 実装 |
|---|---|---|---|
| 地域区分コード | 共通編 1.4 コード一覧（物理21頁） | `11:一級地`〜`17:七級地`、`23:その他`（01〜05 は特別区・特甲地・甲地・乙地・丙地） | **修正**（誤って `01`〜`07` を出力していた。`06` は公式コードに存在しない） |
| 引用規則 | 共通編 1.2.2(4)（物理6頁） | カンマ・ダブルコーテーション・スペース(0x20)・**漢字（2 バイトコード）**のいずれかを含む場合は引用。「漢字」は 2 バイトコードとして定義されている | **修正**（表意文字だけを見ており全角カナ氏名を引用していなかった） |
| ファイル名 | 共通編 1.2.1（物理5頁）／1.7.1（物理51頁） | 英字で始まる半角英数字 8 桁以内 ＋ 拡張子 `.CSV` | **修正**（`kokuho_…_….csv` は不適合） |
| 使用不可能文字 | 共通編 1.2.2(3)① | シングルコーテーション（0x27）は交換情報で使用不可 | **追加** |
| 開始年月日の意味 | 事業所編 開始年月日の設定方法 | 就労継続支援B型（46）は「平成18年4月1日以降における最初にサービス提供した日」。契約支給量の変更があっても変わらず、当月より前の日付になりうる | ADR 0032 の個別入力が正しいことを確認。**契約日以降という検証は誤りだったため下限を 2006-04-01 へ変更** |

## 実装が既に正しかったことを確認した点

## 決定

- 地域区分コードは C# に持たず、出典（`sourceDocumentId` / `sourcePage`）付きの
  `Specifications/region-classification-codes-r7-10.json` に外部化し、
  `RegionClassificationCodeCatalog` が `RegionGrade` → 公式コードを解決する（CLAUDE.md §ハード制約3）。
  表に対応が無い区分（`None`）は fail-close し、推測したコードを出さない。
- `ClaimCsvOfficeDto` は事前解決済みコードではなく `RegionGrade` を運ぶ。CSV のコード体系を
  Application に漏らさない。
- ファイル名は生成側（`ClaimCsvGenerator`）が組み立てる。データ種別 3 桁 ＋ 処理対象年月の下 4 桁
  ＋ 内容の SHA-256 先頭 1 桁で 8 桁とし、同一月に内容の異なる交換情報を複数出しても衝突しない
  （共通編 1.7.2 が同一月の同一ファイル名を避けるよう求めている）。
- 引用判定は「CP932 で 2 バイトになる文字」を仕様のいう「漢字（2 バイトコード）」として扱う。

## 影響

- golden CSV 4 種を再生成した（地域区分 `06`→`16`、全角カナ氏名が引用されるようになった）。
- `IClaimCsvGenerator.Generate` の戻り値を `ClaimCsvDocument(Bytes, FileName)` に変更した。
- `ContractedProvider.Create` の初回サービス提供日の下限を 2006-04-01 とした（契約日との前後関係は制約しない）。

## 残る未確定

- **英数属性の半角英小文字禁止**（共通編 1.2.3③「半角の英小文字は使用できない」）と
  「英数項目に漢字を混在させない／漢字項目に 1 バイト文字を混在させない」は、spec JSON の
  `dataType`（text / code / numeric / date / yearMonth）が公式の属性区分（英数 / 数値 / コード値 / 漢字）と
  1 対 1 対応していないため機械判定できない。属性区分を項目定義へ持たせるまで検証しない。
- `common:outer:control:006` 市町村番号は `const(value=0)` だが、共通編 1.2.3③ はコード値属性の
  全桁 `0` を「未設定として取り扱う」とし、必須項目の未設定はエラーと定める。事業所請求における
  設定値を確認する必要がある。

## 追記: 加算の算定意味論と golden 突合可能性（2026-07-25）

Phase 3-3 で fail-close していた 2 項目の意味論を、登録済み一次資料から確定した。

### 訪問支援特別加算（`provider:J611:01:051`/`:052`、`provider:J611:02:027`/`:028`）

出典: `r8-calculation-note`（留意事項通知 令和8年6月、SHA-256 `0c4f357f4dfd20c7…`）2 の⑹の⑨。
再取得して登録 SHA-256 と一致を確認した。

- 「1 回の訪問に要した時間に応じ、算定するものであること」
- 「所要時間については、**実際に要した時間により算定されるのではなく**、計画に基づいて行われる
  べき指定サービス等に要する時間に基づき算定される」
- 「この加算を 1 月に 2 回算定する場合については、この加算の算定後又は利用後、**再度 5 日間以上
  連続して利用がなかった場合にのみ**対象となる」（「5 日間」は開所日数）

→ **算定回数・算定時間数は「サービス提供回数・提供時間数」とは別概念**であり、日次実績
（`DailyRecord.SpecialVisitSupportMinutes`）から導出できない。公式の実績記録票が提供欄と算定欄を
別に持つのはこのため。ADR 0032 と同じく**個別入力**で供給する。

### 施設外支援（`provider:J611:01:053`/`:054`）

出典: `r6-employment-guidance`（就労移行支援事業、就労継続支援事業（A型、B型）における留意事項に
ついて、SHA-256 `185fa99281ea97b5…`、物理16〜17頁）1(1)。再取得して一致を確認した。

- 「**毎年 4 月 1 日に始まり翌年 3 月 31 日をもって終わる 1 年間**に **180 日間を限度**として算定する。
  なお、この場合の『180 日間』とは、利用者が**実際に利用した日数の合計数**となる」
- 特例（③）: 職場適応訓練、短時間トライアルコースでは 180 日を超えて提供可能
- 留意事項（④ア）: 「同日に施設外支援及び通常の施設利用を行った場合、**施設外支援の実施日として扱う**」

→ `:054`「累計（日／180 日）」は**年度累計**であり、直近 180 日のローリング窓ではない。
当月分（`:053`）は日次記録から算出できるが、年度累計は当月分しか持たない確定 snapshot から
算出できないため**個別入力**で供給する。

### golden CSV の公式突合

公式サンプル CSV および取込テストデータは**公開されていない**（`interface-index-r7-10` の index は
施行分ごとのインタフェース仕様書のみを掲載。共通編・事業所編の「記載例」は帳票 PDF）。
実データでの突合には電子請求受付システムのテスト環境が必要で、電子証明書・伝送を伴うため
CLAUDE.md §責務境界の外である。

→ golden の用途は「意図しないバイト変化の検出」に限定し、**仕様適合は本 ADR のとおり登録済み
一次資料の条文に対して固定する**方針を採る。運用開始時に事業所側で公式システムへの取込テストを
一度実施することを前提とする。
